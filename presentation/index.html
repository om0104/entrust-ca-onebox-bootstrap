unattended · single-host · reboot-safe

Entrust Certificate Authority + CA Gateway
one-box bootstrap

A set of plain-bash scripts that stand up a complete REST-issuing PKI on one Oracle Linux 9 VM — CA, database, directory, HSM client, and the CA Gateway container — then make it survive a reboot with no operator.

Scripts only. No vendor software, installers, images, licences, or docs are included or redistributed — you supply those from your own Entrust entitlement.

Oracle Linux 9 + UEKECA 10.2 CA Gateway 3.8nShield softcard rootless PodmanMIT

The problem it solves

  • CA Gateway 3.8's supported-CA matrix is ECA 8.3 / 10.1.1 / 10.2.
  • So the supported REST-issuance path is CA Gateway 3.8 + an ECA 10.2 CA.
  • Seeing cagw-5501 ("invalid characters")? The CAGW admin's role is missing View activation codes, so the CA masks the code. This is not a version problem.
  • For a lab or a small deployment there is no reason to spread that across hosts — but the build has a dozen easy-to-miss details.

This bundle captures a working reference build as an unattended, resumable pipeline, and documents every prerequisite up front.

What you get

CA

ECA 10.2 root CA, RSA-4096 signing key in an nShield softcard, embedded PostgreSQL 15, 389-ds directory. Cert + CRL published.

Gateway

CA Gateway 3.8 as a rootless Podman Quadlet service, co-resident on the same VM. Mutual-TLS REST API.

Reboot-safe

CA service + boot-persistent softcard preload unit + user-manager linger — everything returns unattended.

Device identities

Two enrolment profiles out of the box: client-generated key (CSR → X.509) and CA-generated key (→ PKCS#12).

Architecture — one VM

requester ──mutual TLS──▶ CA Gateway 3.8 Entrust CA 10.2 :8444 /cagw/v1 ├─ SecurityManager ──XAP 443──▶ ├─ entca.service │ connector ──CMP 829──▶ ├─ PKIX-CMP / ASH / XAP │ ──LDAP 389─▶ ├─ PostgreSQL 15 (local) rootless podman ┘ └─ 389-ds (local) cagw.service (user, linger) signing key │ <inst>-preload.service ── holds `preload … pause` ──────────────────────┘ ▶ nShield softcard

CAGW ↔ CA traffic is local. Two independent trust chains: the ECA CA issues end-entity certs; a small self-signed CA (generated by stage 80) secures the REST endpoint.

The pipeline — ./bootstrap.sh

00 preflight verify OS · UEK kernel · DNS · disk · sudo · media · HSM (no changes) 10 os_prereqs packages · users · firewalld · chrony · fstrim · podman linger 20 nshield_client Security World · enrol module · create softcard · cknfastrc 30 eca_database GPG verify · install PostgreSQL RPM · silent DB setup 40 eca_directory dscreate · load schema (ldapmodify) · CA entry + ACIs 50 eca_engine install CA · config_authority.sh -s -f · init (held preload + expect) 60 eca_systemd autologin · preload unit · stock entca.service · enable · verify ── 70 MANUAL ── ECAA Step D: create the CAGW admin user → ref # + activation code 75 cagw_admin_epf Profile Creation Utility (expect) → admin.epf 80 cagw_config mTLS CA/server/client · render application.yml · licence 85 cagw_run podman load · rootless Quadlet · linger · start 95 verify /status UP → POST enrollments ACCEPTED → openssl verify

Resumable — each stage writes .state/<stage>.done. FORCE=1 ./bootstrap.sh --only 40 re-runs one.

The one manual step

ECA 10.2's control shell has no user/role commands, so one action is done in the Entrust CA Administration (ECAA) 10.2 Windows GUI — about ten clicks:

  • Create user cn=cagw xapv2 — certificate type “Admin Services User Management” (policy OID 2.16.840.1.114027.10.4).
  • Role User Administrator + tick Perform PKIX requests and Create user profile, and make sure View activation codes is on (without it, every enrolment fails cagw-5501); commit the security policy.
  • Record the reference number + activation code.

The bootstrap pauses and prints this exact procedure. Paste the two values into bootstrap.env, re-run — it continues from stage 75. Provide them up front and it never stops.

Host prerequisites — verified by stage 00

OS

Oracle Linux 9.x with the UEK kernel (uname -r ends el9uek). The engine RPM enforces both.

Identity

lowercase FQDN, forward + reverse DNS, real IP in /etc/hosts. ≥ 30 GB free. Root or passwordless sudo. NTP synced.

Packages

net-tools gawk libnsl + PostgreSQL & 389-ds deps + podman + java-11 + expect. Installed by stage 10.

HSM

an nShield Security World reachable as a NetHSM or via RFS. Softcard is created for you. Client authorisation helper included.

Media you provide (not in this repo): ECA 10.2 engine + PostgreSQL RPMs, RPM signing key, Directory Files zip, CAGW image + Profile Creation Utility + licence, Security World Software, ECAA MSI.

Secrets & safety

  • Secrets are generated on first run into ./secrets/*.env (mode 0600) — DB roles, 389-ds, CA Master 1/2/3, First Officer, softcard passphrase, CAGW EPF. Re-runs reuse them. Back up ./secrets/ — no other copy of the Master User passwords exists.
  • .gitignore excludes secrets, media, state, and every key / cert / licence extension.
  • Stage 20 never re-initialises a Security World and skips softcard creation if it exists.
  • The HSM client-authorisation helper backs up the hardserver config and aborts if any existing client record would change.
  • No stage deletes data.

The device-identity API

Mutual TLS required. Subjects are built X.500 root-first (CN last) — the connector reverses RDN order.

Model A · device key

POST …/enrollments
{ "profileId": "0",
  "requiredFormat": {"format":"X509"},
  "csr": "<b64 DER PKCS#10>" }
→ ACCEPTED · X.509 leaf + chain
key never leaves the device

Model B · CA key

POST …/enrollments
{ "profileId": "1",
  "requiredFormat": {"format":"PKCS12",
    "protection":{"type":"PasswordProtection",
                  "password":"…"}},
  "optionalCertificateRequestDetails":
    {"subjectDn":"cn=dev,ou=CA,dc=…"} }
→ ACCEPTED · PKCS#12
needs “Generate key at client” unchecked in ECAA

Renew = new CSR, same subject. Revoke = POST …/certificates/{serial}/revocations.

Run it

git clone https://github.com/om0104/entrust-ca-onebox-bootstrap.git
cd entrust-ca-onebox-bootstrap
cp bootstrap.env.example bootstrap.env
$EDITOR bootstrap.env          # identity · HSM · media paths · licence values

./bootstrap.sh                 # stages 00 → 95, resumes where it stopped
./bootstrap.sh --only 95       # re-verify any time
REBOOT=1 ./bootstrap.sh --only 95   # full one-box reboot test
